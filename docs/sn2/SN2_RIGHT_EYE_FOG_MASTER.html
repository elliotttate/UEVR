SN2 Right-Eye Fog Bug — Master Findings Document

Session: 2026-05-22. Game: Subnautica 2 (UE 5.6.1) running under UEVR with -emulatestereo. Headset: Meta XR Simulator. Status: stable partial fix shipped; full match blocked on architectural heap-aliasing issue.

TL;DR: Right eye renders without fog tint by default (looks like a desert through the cave opening). The engine's natural unfixed output for the right viewport is actually dark/black; UEVR's per-view fog patches make it render at all but with broken stereo data. We bisected 11 UEVR built-in fixes down to 1 load-bearing builtin, fixed a critical bug in our own FixRuleEngine that silently dropped rules, and identified the remaining blocker as placed-heap aliasing between mirror and original GPU resources.

1. The bug

Under -emulatestereo, UE5 renders both left and right eye viewports but doesn't replicate all compute/material passes per-view. The fog producer VoxelizePS (PS CRC 0x9D14FCF0) only fires on left eye, writing the IntegratedLightScattering 3D volume with left-frustum projection. Right eye's basepass MainPS reads the same volume but with right-eye matrices, sampling cells the left projection never populated — result is missing fog tint, sky shows through.

2. Key findings

1. The "white right eye" is the engine's natural unfixed output

Disabling all 11 UEVR_SUBNAUTICA2_* builtins (master kill via UEVR_DISABLE_SN2_HOOKS=1 wasn't enough — they have their own gates) makes the right eye render dark, not white. The white sky comes from UEVR's per-view fog fixes triggering the fog chain to execute on right eye but with broken per-view data.

2. Only 1 of 11 UEVR_SUBNAUTICA2_* builtins is load-bearing

Bisection (states B → B3 → B3a → B3b): only UEVR_SUBNAUTICA2_DISABLE_UNDERWATER_FOG_VIEW_DATA_FIX = 0 needs to be enabled to trigger the fog chain on both eyes. The other 9 disabled-by-default builtins (LEGACY_FOG_UNIFORM_MUTATIONS, SETUP_VOLUMETRIC_FOG_UB_HOOK, LIGHTSCAT_STORE_MIDHOOK, etc.) are not required.

3. FixRuleEngine had a critical ordering bug

Until commit ba9279f, the Skip-mode early-return in sn2_try_duplicate_slw_basepass_right fired BEFORE the FixRuleEngine consultation. This silently dropped any rule that tried to override a skip-mode PSO (like VoxelizePS). Fixed: FixRules now consulted first.

4. Mirror RTV redirect works but LEFT eye corrupts

With the FixRules bug fixed, VoxelizePS gets synth_right_cb mode + mirror RTV redirect. OMSetRenderTargets binds mirror RTVs correctly. Dup draws complete. But LEFT eye renders with chunky pixel artifacts in the underwater fog area — indicates placed-heap aliasing between mirror and original GPU memory.

5. Critical bug found + fixed in UEVR

Skip-mode early-return fired before FixRules consultation

In sn2_try_duplicate_slw_basepass_right, the dup function had this flow (pre-fix):

  1. Compute dup_mode = sn2_dup_config::mode_for(ps_crc)
  2. If dup_mode == Skip, return. ← early exit here
  3. (Phase FF) Consult sn2_fix_rules::find_rule() — never reached for skip-mode PSOs

Any PSO whose dup_cfg said "skip" could never be overridden by a fix rule. The whole Phase FF declarative override mechanism was silently broken for the most common case.

Diagnostic that found it

Enabled UEVR_SN2_DUP_TRACE_CRCS=0x9d14fcf0 in the dup function. VoxelizePS showed 91 entries to the dup function but 0 FixRules applies. Combined with SN2-DupTrace2 logging mode=2 (Skip), traced the issue to the early-return ordering.

Fix (commit ba9279f)

Reordered: FixRules consultation now runs first, then Skip-mode early-return if no rule changed it. PSOs with override rules continue past the gate.

6. The remaining blocker: heap aliasing

With FixRules now correctly firing, the synth dup flow works end-to-end:

VoxelizePS LEFT-eye native draw │ writes to IntegratedLightScattering (original) ▼ Our dup function fires (post-LEFT-draw hook) │ ├─ Set viewport to right ├─ Bind synth donor's right-eye CB at root 3 ├─ OMSetRenderTargets(mirror RTVs) ← redirects writes to mirror ├─ Re-issue draw → writes to mirror (right-projected) └─ Restore original viewport + RTV bindings LEFT eye should be unaffected. But it isn't.

Evidence of aliasing

  • Mirror RTV creation logs fire correctly: [SN2-GfxRtvRedirect] created mirror RTV for resource 0x... fmt=26 dim=54x30x48
  • OMSetRenderTargets binds mirror RTVs before dup draw
  • OMSetRenderTargets restores originals after
  • Despite this, LEFT eye basepass output shows chunky pixel artifacts in the fog area

Hypothesis

D3D12 placed-resource virtual address aliasing — the mirror resource's GPU memory range overlaps with the original via the underlying virtual address space, even though they're separate ID3D12Resource instances. Writes to the mirror physically land on memory the original RTV's view also covers, so when LEFT-eye basepass samples the original, it reads partially-mirror-overwritten data.

Documented separately in sn2_aliasing_CONFIRMED_definitive_2026_05_21.md from a prior session.

8. Three paths to full fix (next session)

Path A — Verify mirror allocation is alias-safe

Sn2UweFogMirrorHook uses CreateCommittedResource which should allocate from a fresh heap. But the underlying GPU VA could still alias with the original. Nsight Graphics has a memory layout view that can confirm/deny. If aliased, switch to ID3D12Heap with explicit size + alignment that guarantees no overlap with game-owned heaps.

Path B — Wire consumer SRV redirect BLOCKED

The code exists at D3D12Hook.cpp:sn2_try_begin_consumer_srv_redirect but is gated by UEVR_SN2_CONSUMER_SRV_REDIRECT=1. Tested live in M4 (Phase SS): game hung/no-response after 2 frames. Only 1 redirect fired before stall. The per-draw 21+ heap iteration is likely the deadlock cause. Path B requires significant refactor of the consumer redirect code before retry.

Path C — DXIL VoxelizePS patch

Modify VoxelizePS to be eye-aware: read eye index from CB, compute matrices per-eye, output to right slice for right eye / left slice for left eye. Eliminates the need for the dup mechanism entirely. Bigger work (DXIL editor needed) but architecturally cleanest.
